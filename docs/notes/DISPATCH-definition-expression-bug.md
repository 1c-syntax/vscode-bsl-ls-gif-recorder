# Диспатч: Go to Definition не работает для вызова метода внутри выражения

> Самодостаточное задание для отдельной сессии в репозитории
> `1c-syntax/bsl-language-server`. Подход: **сначала падающий тест, подтверждающий
> root cause, затем фикс**. Ветку брать от свежего `develop`.

## Симптом

В `.bsl`-модуле «Перейти к определению» (textDocument/definition, F12) **не находит**
объявление метода, если вызов стоит **внутри выражения**, и **находит**, если тот же
вызов стоит **отдельным оператором**.

| Код | F12 на имени метода | Факт |
|---|---|---|
| `Сложить(2, 3);` (оператор) | → объявление `Функция Сложить` | ✅ резолвится |
| `Сумма = Сложить(2, 3);` (в выражении) | → ожидается объявление | ❌ «No definition found» |

Воспроизведено вручную в редакторе (code-server) на сборке `develop`; контраст снят
двумя идентичными фикстурами, отличающимися только контекстом вызова (оператор vs
правая часть присваивания).

### Сопутствующие наблюдения (проверить, вероятно та же причина)
- Идентификатор в правой части присваивания не резолвится: в `Значение = Параметр;`
  F12 на `Параметр` → «No definition found». При этом на левой части (`Счётчик = ...`,
  `НастройкиМодуля = ...`) и в объявлениях `Перем` — резолвится.
- Гипотеза, которую нужно подтвердить/опровергнуть тестами: **ссылки, находящиеся в
  выражениях (RHS, аргументы, вложенные вызовы), не попадают в индекс ссылок**, тогда
  как операторные вызовы и LHS-цели — попадают. Возможно, баг шире, чем только методы.

NB: `Сообщить(...)`, `СтрНайти(...)` и т.п. — платформенные методы без исходного
определения, для них «No definition found» — корректно, это НЕ предмет данного бага.

## Где искать

`DefinitionProvider` целиком делегирует в `ReferenceResolver.findReference(uri, position)`:

- `src/main/java/.../providers/DefinitionProvider.java` — тонкая обёртка, править не нужно.
- `src/main/java/.../references/ReferenceResolver.java` — поиск ссылки по позиции.
- **`src/main/java/.../references/ReferenceIndexFiller.java`** — главный подозреваемый:
  визитор AST, наполняющий индекс ссылок. Проверить, какие узлы грамматики он
  посещает для вызовов методов — вероятно обрабатывается операторный вызов
  (`callStatement`/`statement`), но не вызов метода внутри `expression`
  (`complexIdentifier`/`methodCall`/`globalMethodCall` в выражении).
- Смежные финдеры: `SourceDefinedSymbolDeclarationReferenceFinder`,
  `ReferenceIndexReferenceFinder`.

## План (тест → фикс → тест)

### 1. Падающий тест (подтверждает root cause)
Тест-класс: `src/test/java/.../providers/DefinitionProviderTest.java`
(`@SpringBootTest`, уже есть `testDefinitionOfLocalMethod`, который покрывает ТОЛЬКО
операторный вызов — см. фикстуру).

Фикстура: `src/test/resources/providers/definition.bsl`. Сейчас:
```bsl
Функция ИмяФункции(Знач П1) Экспорт

КонецФункции

ИмяФункции();                         // ← операторный вызов (этот случай тест уже покрывает)

Справочники.Справочник1.ТестЭкспортная();
```
Добавить строку с вызовом в выражении, например:
```bsl
Рез = ИмяФункции();                   // ← вызов в выражении (сейчас НЕ резолвится)
```
Добавить тест по образцу `testDefinitionOfLocalMethod` (структура `// given / // when /
// then`, англоязычное имя метода):
```java
@Test
void testDefinitionOfLocalMethodInsideExpression() {
  // given
  var documentContext = TestUtils.getDocumentContextFromFile(PATH_TO_FILE);
  var methodSymbol = documentContext.getSymbolTree().getMethodSymbol("ИмяФункции").orElseThrow();

  var params = new DefinitionParams();
  params.setPosition(new Position(/* строка с "Рез = ИмяФункции();" */, /* колонка внутри имени */));

  // when
  var definitions = definitionProvider.getDefinition(documentContext, params);

  // then
  assertThat(definitions).hasSize(1);
  assertThat(definitions.getFirst().getTargetSelectionRange())
    .isEqualTo(methodSymbol.getSelectionRange());
}
```
Прогнать — тест должен **упасть** (вернётся пустой список). Это подтверждает root cause.

### 2. Фикс
В `ReferenceIndexFiller` (или соответствующем визиторе) обеспечить регистрацию ссылки
на метод и для вызовов внутри выражений. Проверить заодно идентификаторы в RHS —
если причина общая, тем же изменением покрыть и их (добавить тест на RHS-переменную/
параметр). Не расширять охват «вслепую» — каждое расширение покрывать тестом.

### 3. Проверка
- Новый тест и существующие `DefinitionProviderTest` — зелёные.
- Прогнать затронутые наборы (как минимум `DefinitionProviderTest`,
  `ReferenceIndexFiller*Test`/`ReferenceResolver*Test`, если есть).

## Конвенции репозитория (из практики этого проекта)
- По одному коммиту на подзадачу; перед каждым коммитом — прогон тестов.
- Тесты: структура `// given / // when / // then`; идентификаторы латиницей
  (без translit вида `summa`), осмысленные англоязычные имена тестов.

- Ветку открыть от свежего `develop`, не коммитить в `develop` напрямую; после коммита —
  push, затем PR в `develop`.
