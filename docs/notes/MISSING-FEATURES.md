# Пробелы bsl-language-server (кандидаты на issue)

Найдено при записи демо-каталога провайдеров (стенд `bsl-gif-demo`, code-server + внешний
develop-jar, Java 25, реальная конфигурация SSL `1c-syntax/ssl_3_2` пин `4a4513f8`).
Каждый пункт проверен эмпирически на ПОЛНОСТЬЮ прогретом контексте (статусбар без
«Наполняем контекст…»). Ниже — готовые заготовки для ишузов.

---

## 1. Completion: общий модуль не предлагает экспортные методы после точки

**Провайдер:** CompletionProvider (BSL).
**Серьёзность:** missing feature.

**Шаги:**
1. Открыть конфигурацию (контекст полностью построен).
2. В модуле набрать `ОбщегоНазначения.` (или имя любого общего модуля + точка).

**Ожидается:** список экспортных методов общего модуля (по аналогии с тем, как
`Справочники.Валюты.` предлагает методы менеджера).

**Фактически:** список автодополнения НЕ появляется вовсе.

**Контраст (работает корректно):**
- `Справочники.Валюты.` → методы менеджера, включая кастомные из модуля менеджера
  (Выбрать, НайтиПоКоду, КодыВалют, КурсВалютыПоФормуле, …).
- `Перечисления.ВажностьПроблемыУчета.` → члены менеджера и значения.
- `ТаблицаЗначений` / `Структура` через точку, локальные переменные, методы модуля,
  глобальные функции, ключевые слова — всё предлагается.

**Важно:** Go-to-definition (F12) и Find-references на вызовах методов общего модуля
работают (есть отдельные сценарии def-08/refs-01). Отсутствует ИМЕННО автодополнение
членов по `ИмяОбщегоМодуля.`.

**Где копать:** completion-провайдер обрабатывает платформенные глобали и менеджеры
метаданных (Справочники/Документы/Перечисления), но не отдаёт экспортные методы общих
модулей при member-access. Источник членов общего модуля уже есть в индексе типов
(`CommonModule.<Имя>`), используется для definition/hover.

## 2. Definition/References: нет перехода по имени модуля в `ОбщийМодуль("ИмяМодуля")`

**Провайдер:** DefinitionProvider / ReferenceIndexFiller.
**Серьёзность:** missing feature.

**Шаги:**
1. `Модуль = ОбщегоНазначения.ОбщийМодуль("УправлениеПечатью");`
2. Поставить курсор на строковый литерал `"УправлениеПечатью"`, нажать F12.

**Ожидается:** переход к общему модулю `УправлениеПечатью`.

**Фактически:** ничего (на литерале нет ссылки).

**Контраст (работает):**
- F12 на аксессоре `ОбщегоНазначения` → переход к этому общему модулю.
- F12 на `Перем.Метод()`, где `Перем = ОбщегоНазначения.ОбщийМодуль("…")` → переход к
  методу нужного модуля (маппинг переменной уже ведётся).

**Где копать:** `ReferenceIndexFiller.VariableSymbolReferenceIndexFinder.visitAssignment`
для паттерна `Перем = ОбщегоНазначения.ОбщийМодуль("Имя")` ведёт `variableToCommonModuleMap`,
но НЕ вызывает `index.addModuleReference` на range строкового литерала → у
DefinitionProvider нет Reference. Имя модуля и его mdoRef уже доступны через
`ModuleReference.extractCommonModuleName` в том же месте — достаточно добавить ссылку на
литерал. Аксессоры настраиваются `ReferencesOptions.commonModuleAccessors`. Подробности —
`FINDINGS-definition-editor.md`.

## 3. (Перенесено из ранней заметки — требует перепроверки) TYPE_NAME для неинстанцируемых типов

**Провайдер:** TypeRegistry / резолв типов.

Голое имя типа без конструкторов (неинстанцируемый тип) не резолвится; предполагаемый фикс —
в `TypeRegistry.registerPack`. Найдено ранее в этом проекте, в текущей сессии НЕ
перепроверялось — перед заведением ишуза подтвердить актуальным репро.

---

## Проверено и работает (НЕ баги — для протокола)

completion: глобальные функции, методы объекта по выводу типа (Новый …), типы после Новый,
локальные переменные, процедуры/функции модуля, члены коллекций (ТаблицаЗначений),
коллекции метаданных (`Справочники.`), члены менеджера справочника (`Справочники.Валюты.`),
члены/значения перечисления, ключевые слова и сниппеты; OneScript — классы библиотеки после
`Новый` и методы модуля библиотеки **при наличии `#Использовать` (или если файл в том же
пакете)**; без `#Использовать` и вне пакета — корректно «No suggestions».

## 4. Completion: значения перечисления не предлагаются после точки

**Провайдер:** CompletionProvider (BSL). **Серьёзность:** missing feature (как #1/#3988).

**Шаги:** `Перечисления.ВажностьПроблемыУчета.` (контекст построен).

**Ожидается:** значения перечисления (`Ошибка`, `Предупреждение`, `ВажнаяИнформация`, `Информация`, `ПолезныйСовет`) + методы менеджера.

**Фактически:** только методы менеджера (`Индекс`, `Получить`, `ПолучитьФорму`, `ПустаяСсылка`…). Значений НЕТ: `Перечисления.ВажностьПроблемыУчета.Ошиб` → пустой попап.

**Проверено** реальным LSP-прогоном на SSL (свежий develop, fixture metadata/designer + конфигурация ssl_3_2). Ловушка: `.Пред` показывает `Предупреждение`, но это платформенный глобал `Предупреждение()`, а не значение перечисления (совпал по префиксу) — юнит-тест/беглый просмотр обманывают, нужен LSP-прогон.
