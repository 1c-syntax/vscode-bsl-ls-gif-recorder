# Наблюдения: Go to Definition в редакторе vs юнит-тесты (краевые случаи)

> Зафиксировано 2026-06-01 при записи демо. **Это НЕ подтверждённый баг кода** — есть
> расхождение «редактор падает / юнит-тест проходит», вероятно завязанное на отсутствие
> распознанной конфигурации в bare-проекте. Перед любым диспатчем — подтвердить в контексте
> распознанной конфигурации (см. связь с SSL-блокером). Урок прошлого: поспешный диспатч уже
> оказывался ложной тревогой из-за устаревшего jar.

## Окружение

- Стенд code-server (этот репозиторий, см. RUNBOOK.md), внешний jar.
- jar — **свежий develop** (ветка `feature/hover-...` ребейзнута на develop `c72dcf9831`),
  содержит майские фиксы резолва ссылок (`91120f21cc`, `dde2a510a3`, `e24d93ff08`,
  `0aa08b22cc` — все предки HEAD). Версия `0.0.0-DEV`.
- Воркспейс — **одиночный `.bsl`-файл без конфигурации** (нет `Configuration.xml`).

## Что РАБОТАЕТ в редакторе (F12)

| Случай | Фикстура |
|---|---|
| Вызов процедуры (оператор) | `ВывестиПриветствие();` → объявление |
| Вызов функции в выражении (экспортная, объявлена выше) | `Сумма = Сложить(2,3);` при `Функция Сложить(...) Экспорт` выше → объявление |
| Локальная переменная | `Счётчик = ...` → `Перем Счётчик` |
| Модульная переменная | `НастройкиМодуля = ...` → `Перем НастройкиМодуля Экспорт` |
| Peek (Alt+F12 / палитра) | инлайн-просмотр определения |

## Что НЕ переходит в редакторе («No definition found»)

1. **Параметр в правой части выражения**
   ```bsl
   Процедура Тест(Параметр)
       Значение = Параметр;   // F12 на «Параметр» → No definition found
   КонецПроцедуры
   ```
2. **Не-экспортная функция, вызванная в выражении ДО её объявления**
   ```bsl
   Процедура Тест()
       Сумма = Сложить(2, 3);   // F12 на «Сложить» → No definition found
   КонецПроцедуры

   Функция Сложить(Первое, Второе)   // объявлена НИЖЕ, без Экспорт
       Возврат Первое + Второе;
   КонецФункции
   ```
   (Та же функция, вызванная **оператором** `Сложить(2,3);`, — переходит. Экспортная функция,
   объявленная **выше**, в выражении — тоже переходит.)

## Расхождение с юнит-тестами

Другая сессия (отдельный worktree `definition-expression` репозитория LS) на свежем develop:
- `DefinitionProviderTest.testDefinitionOfLocalMethodInsideExpression` (`Рез = ИмяФункции();`) — **PASS**;
- probe: параметр в RHS (`Значение = П1`) — **PASS**;
- probe: локальная переменная в RHS (`Итог = Значение`) — **PASS**.

Юнит-тесты используют серверный контекст, построенный из **тестовой конфигурации**
(`initServerContextOnce(PATH_TO_METADATA)`). В редакторе же — bare-проект **без конфигурации**.

## Гипотеза

Расхождение, вероятно, связано с тем, что в воркспейсе **без распознанной конфигурации**
часть ссылок не индексируется так, как в контексте конфигурации. Это та же тема, что и
блокер межмодульной навигации на SSL (LS не запускал фазу «Рассчитываем данные конфигурации»).

## Как подтвердить/опровергнуть

Повторить кейсы 1–2 в воркспейсе с **распознанной конфигурацией** (например, после починки
детекта SSL). Если там переходят — проблема в обработке bare-проекта без конфигурации, а не в
самом резолве. Только после этого — решать про диспатч.

Связано: блокер SSL-конфигурации (детект `src/cf`), [[project_task_definition_expression_bug]].

## Находка 2026-06-01: F12 на `ОбщегоНазначения.ОбщийМодуль("ИмяМодуля")`

Проверено на реальной SSL (РаботаСКурсамиВалют, стр. 545:
`МодульУправлениеПечатью = ОбщегоНазначения.ОбщийМодуль("УправлениеПечатью");`), Java 25, develop-jar.

- **F12 на строковом литерале `"УправлениеПечатью"` → НЕ переходит** к общему модулю
  `УправлениеПечатью` (новая вкладка не открывается, курсор остаётся на строке). Перехода к
  определению по имени модуля в строке нет.
- **F12 на самом аксессоре `ОбщегоНазначения` → переходит** к общему модулю `ОбщегоНазначения`
  (как к обычному идентификатору общего модуля; то же поведение, что в def-06/08).

**Почему (код):** `ReferenceIndexFiller.VariableSymbolReferenceIndexFinder.visitAssignment` для
паттерна `Перем = ОбщегоНазначения.ОбщийМодуль("Имя")` (или `ОбщийМодуль("Имя")`) лишь ведёт
маппинг `переменная → mdoRef общего модуля` (`variableToCommonModuleMap`), чтобы разрешать
последующие вызовы `Перем.Метод()`. На позиции строкового литерала `index.addModuleReference`
НЕ вызывается → у `DefinitionProvider` нет Reference для резолва. Аксессор же получает ссылку в
`addModuleReferenceForCommonModuleIdentifier`. Аксессоры настраиваются через
`ReferencesOptions.commonModuleAccessors`.

**Вывод:** это пробел/возможность для доработки (добавить Reference на строковом литерале имени
модуля внутри `ОбщийМодуль("...")`), а не баг существующего поведения. Маппинг
переменная→модуль уже есть — координаты литерала тоже доступны в `extractCommonModuleName`.
